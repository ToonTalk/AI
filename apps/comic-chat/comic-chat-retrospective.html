The Making of Web Comic Chat

One conversation, twenty-one versions: how a faithful port of Microsoft Comic Chat (1996) was published as a claude.ai artifact, broke in instructive ways, and was debugged — by Ken Kahn and Claude — through every wall the artifact sandbox and one stubborn Android WebView could put up.

✱ THE PORT ARRIVES ✱

Ken's single-file port — layout engine, balloon routing, emotion wheel, seeded deterministic re-layout — is published byte-for-byte as an artifact (md5-verified). It works on the first try, which is the last time anything does on the first try.

The sandbox has opinions.

First discoveries: localStorage quietly works in artifacts despite documentation saying otherwise, and dialogs quietly don't.

✱ THE ONE-CHARACTER MYSTERY ✱

After a restart, every line of a saved strip is spoken by the same character, one utterance per panel. The cause is a boot-order race: state validation runs before the artwork restores, the style resets, and the recast-by-position remap maps every unrecognized id to its fallback.

Every line falls back to the first character.

Ken's own code comment had predicted the failure. The fix: make the remap idempotent. Meanwhile the Clear button had never worked at all — confirm() is silently ignored in the sandboxed iframe.

✱ FEATURES LAND ✱

A general undo stack with Ctrl-Z (snapshots on every mutation), an opt-in AI toggle with a first-enable tip, and AI replies rebuilt on the keyless artifact API after window.claude.complete turned out to no longer exist.

Why is Scotty's face frozen?

Because torsos cycled through variants but faces didn't. pickFace gained the same round-robin lastFace mechanism as pickTorso, and the AI prompt now names each character's previous expression and asks for a different one. Naming several characters makes them all reply, in order of mention, each seeing the replies before theirs.

✱ TYPE MATTERS ✱

Comic Sans MS is Microsoft's and cannot be embedded — but Comic Neue (SIL OFL) can, subsetted to 17 KB per face. It rides behind Comic Sans in every font stack, so Windows keeps the authentic 1996 look while Linux and Android get a real comic face instead of a fallback serif.

measureText never loads a font.

Two traps: canvas measurement doesn't trigger @font-face loading (load explicitly, then re-measure and re-render once), and SVG serialized into an image can't see page styles — the font CSS is injected into every exported panel.

✱ TWO MEGABYTES versus THE SANDBOX ✱

The original artwork is a 2.27 MB artpack that had to reach the artifact somehow. The sandbox disagreed at every turn: cross-origin fetch is blocked by CSP even from CORS-open hosts; the JSON link opens as a wall of text; downloads vanish. Countermeasures, in escalating order: a ZIP served for real downloads, read by a forty-line central-directory parser over the browser's native DecompressionStream; gzip-compressed localStorage; a setup screen that stopped being once-only after its flag wrongly suppressed it; and a copy-and-paste route that ran into physics —

A copy tops out near 400 KB of characters.

Android's clipboard rides binder IPC with a hard 1 MB transaction buffer, and text travels as UTF-16 — so the pack was split into six parts with an accumulator that recognizes truncation, strips Chrome's share-decoration (curly quotes plus an appended URL), and installs the moment the concatenation parses.

✱ THE ANDROID CAMPAIGN ✱

The Claude app's WebView closed nearly every door: the file picker wouldn't open, links opened in-app instead of a browser, clipboard promises hung forever without resolving or rejecting (every gated call now races a timeout so silence is impossible), and the composer's stacked height starved the strip to a sliver — fixed with a collapsible cast-and-emotion panel.

Move the interface, not the keyboard.

Viewport meta tags are inert inside an iframe the artifact doesn't own, and visualViewport reported nothing — so while typing on a phone, the message row pins itself to the top of the screen, the one region a keyboard never covers, and drops back on send.

✱ THE ONE-MEGABYTE WALL ✱

Embedding everything seemed cleaner than transferring it. The publish button disagreed:

File is too large.

2.28 MB rejected, 1.56 MB rejected, 917 KB accepted — an undocumented cap bracketed by experiment. The answer is the hybrid: a 15-character starter cast (gzip + base64, inflated at boot) embedded under the cap, with the full 31 one file-picker tap away, taking precedence forever once loaded. Lossless PNG recompression was measured at only 12%, closing the door on ever embedding the whole pack.

✱ THE MIND MAKER CLUE ✱

Ken found the decisive evidence: another artifact of his where downloads and file dialogs simply worked. Comparing code isolated the mechanisms — blob URLs where data: URLs are blocked, and a dynamically created, never-attached file input where a hidden static one is refused.

One existence proof beats ten hypotheses.

Two more laws followed from later failures: user activation is a budget spent by time (open the window inside the tap, fill it after the seconds-long compose), and blobs are for handing bytes to other machinery while data: URLs are for display — the sandbox's opaque origin can't resolve its own blobs in an <img>.

✱ IT WORKS — AND SAYS WHERE IT DOESN'T ✱
Working fine on my phone!

In a browser tab, everything: starter cast on load, full pack via the picker, comics saved. Inside the Claude app, a dismissible notice (keyed on the WebView's wv user-agent token) says plainly that saving comics and loading extra characters need a real browser — and that everything else works. Honest signposting instead of mysterious buttons.

✱ FINISHING TOUCHES ✱

*waves* Hello there! now produces an action caption and the spoken balloon together — and after checking the visual record of the original (period strips show narration captions sharing panels with balloons), the panel rule was refined to one balloon and one caption per character per panel, making co-location more faithful than the port's old separation. Plus: "Save comic" instead of PNG jargon, tooltips throughout, and a link to Ken's post about building the app.

✱ ERRATA — THE ASSISTANT'S OWN PANELS ✱

For the record, bugs Claude introduced and later ate: hiding an overlay with .hidden against an inline display:flex (the attribute loses); "improving" the overlay image to a blob URL and breaking it on Android; twice sequencing gated APIs after the user activation had expired; a once-only greeting flag that suppressed the setup screen exactly when it was needed; and a fidelity claim about action panels asserted more confidently than the evidence supported.

Debugging is symmetric.
✱ WHAT SURVIVES THE CONVERSATION ✱

Twenty-three verified lessons about the artifact sandbox — downloads, pickers, clipboard ceilings, publish caps, keyboards, fonts, activation — now live in three places: Claude's persistent memory, a knowledge document for a Claude Project, and an on-demand skill for Claude Code. The next artifact starts where this one finished.
